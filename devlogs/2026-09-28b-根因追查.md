## 1. 三个隔离实验（这是本次最有价值的产出）

我造了三个**独立于贪吃蛇**的最小实验，把"学习链路"和"游戏/奖励"彻底分开。
三个工具都在 `tools/`，可独立编译运行，只读、不碰训练。

### 1.1 `bandit_check.cpp` —— 单状态老虎机（已知最优解）

**问题**：REINFORCE 的梯度四步写得对不对？
**方法**：输入恒定（单状态），6 臂，第 2 臂 μ=1.0 最优。用**和 `Trainer` 完全相同的**
网络类型与梯度四步。

```
步  60000 | 选最优臂占比 99.7% | argmax=2 ✅最优 | p(最优臂)=0.9999
判定: ✅ 学习器【正确】
```

**结论**：反向传播、softmax 交叉熵梯度、基线、采样、更新顺序 —— 全部正确。

### 1.2 `statebandit_check.cpp` —— 上下文老虎机（必须学条件策略）

**问题**：网络能不能学会"**看输入决定动作**"？
**方法**：输入 2 维（1 个 context bit + 1 个常量）。ctx=0 时最优臂 2，ctx=1 时最优臂 4。
最优策略**必须是条件策略**。

```
最终 ctx=0 的 argmax : 2  (最优 2)  ✅
最终 ctx=1 的 argmax : 4  (最优 4)  ✅
全程选对率 99.5%   (全随机 = 16.7%)
判定: ✅ 网络【能】学会条件策略
```

**结论**：结构 + 梯度 + 优化器**支持**"输入不同 → 动作不同"。
⚠️ 注意：这个实验只有 2 维输入，而蛇是 33 维。**结论不能直接等价迁移**。

> ★★ **为什么必须补做 1.2**：1.1 的输入是**常量**，所以"最优策略 = 一个常量输出"，
> 只要学会设偏置就能满分 —— **它证明不了网络能不能用输入**。
> 这是我这次排查中踩的最大的一个坑：**用了一个测不出目标性质的实验，还差点当成结论。**

### 1.3 `sens_check.cpp` / `perturb_check.cpp` —— 蛇网络到底在算什么

**问题**：训练出来的蛇网络，输出到底依不依赖输入？
**方法**：加载训练后的权重，喂 10 种**极端不同**的观测（食物正前 / 正后 / 正左、
正前方贴墙、圈在正前 / 正后、全 0、全 1、随机…）。

```
训练 600 局之后的权重：
  全部输入 = 0            → argmax 右转
  全部输入 = 1            → argmax 右转
  食物在【正前方】(120px)  → argmax 右转
  食物在【正后方】(120px)  → argmax 右转
  正前方 30px 是墙        → argmax 右转
  当前圈在正前方(600px)    → argmax 右转
  当前圈在正后方(600px)    → argmax 右转
  随机观测(0~1)           → argmax 右转

出现的不同 argmax 个数 : 1 / 6
判定: ❌ 网络【完全无视输入】
```

`perturb_check` 给出量化结果：

```
平均灵敏度 ‖Δlogit‖ : 0.075   （输入每变 0.20）
logit 幅度（决策差距）: 1.510
★ 要把 argmax 翻过来，输入需要变化 : 4.01
  （真实观测各维的逐帧变化量级是 0.001 ~ 0.2）
```

**结论**：灵敏度**不是零**，但"决策差距 / 灵敏度" = 20 倍 ——
**在真实输入的变化范围内，argmax 永远不会翻。**

## 2. 被实验推翻的假设（如实登记）

我在这次排查里提过多个假设，全部被数据推翻。记下来，避免后人重走：

| 假设 | 推翻它的实验 | 结果 |
|---|---|---|
| `entropyCoef = 0.1` 太强，熵项主导梯度（曾算"475 倍"） | CSV 实测 `entGradNorm / gradNorm` | **0.1%**。假设错 |
| `rWallDanger/rEnemyDanger` 让"撞死比贴墙便宜" | 负责人指出 + 面板实测 | 负责人对：**不是扣分主导** |
| `fed`（吃饱余韵）在往梯度里灌噪声 | `--ablate no-fed`，5 种子 | **关掉全线更差**。假设错 |
| 梯度尖峰把权重踹飞 | `--gradclip 1.0`，多配置 | **无改善**。假设错 |
| 学习率太大导致不稳 | `--lr 0.005` / `+clip` | **无改善**。假设错 |
| `w_in` 太小 / `tanh` 饱和吃掉回传梯度 | `win_scale_test.exe` 放大 `w_in` 1~8 倍 | 所需输入变化 4.01→2.29，**仍 >2**。假设错 |
| 观测与奖励时序错位 | 逐步核对 `Arena::step` 与 `EpisodeRunner::tick` | **完全对齐**。假设错 |
| ε-greedy 随机步造成 off-policy 偏差 | 代码审查 + 修复 | 是真问题但**不是主因**（修完仍学不会） |

> ★★ **教训**：本次 8 个假设，**8 个都错**。
> 共同错误模式是：**从间接读数（某个统计量）直接跳到"机制是 X"**，
> 而没有先做**能直接判定 X 的最小实验**。
> 正确的顺序是：**先造能直接测 X 的工具，再看 X 是否成立。**

## 4. 实测到的其它硬事实（供后续参考）

- **回报 ≈ 吃食数**：`corr(reward, food) = 0.93`
- **噪声极大**：单局回报 均值 2.5 / 标准差 52.6（比值 21）
- **梯度方向基本是噪声**：800 局参数累计走 21.6，**净位移只有 0.287**（98.7% 相互抵消）
- **`gradNorm` 与单局回报相关 0.37** → **步长主要由"这一局运气好不好"决定**
- **每局参数只移动 0.3~0.5%**（`updateNorm/paramNorm`）
- **三个种子的形状一致**：吃食数**第 200~400 局见顶后回落**
  （这正是负责人报的"reward 越跑越低"）
- **锁死局占比随训练单调上升**：16.2% → 32.9% → 61.4% → 82.9% → **98.8%**
- **`entGradNorm / gradNorm = 0.1%`** → 熵项**不是**问题（我之前的猜测错了）
- 学习器**能**在有信息时收敛：`statebandit_check` 99.5%

**下一步（未完成，需继续）**：在**不靠假设**的前提下找出"训练为什么会收敛到恒定策略"。
目前唯一还没被证伪、也没被证实的方向是**梯度信噪比**：
- 需要直接测量 `‖E[g]‖ / √Var[g]`（信号/噪声比），而不是用间接统计量推断
- 判据：若该比值 ≪ 1，则问题在"样本量 vs 噪声"，修法是降方差（per-step advantage / 更大批量 / 更长训练）
- 若该比值正常，则说明梯度方向是对的，问题在别处 —— 那必须换一个能直接判定方向的手段
