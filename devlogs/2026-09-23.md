## 2. ★ 最重的一个 bug：`encoder.h` 越界写 96 字节

### 症状

`train_probe` 跑完第 0 个训练回合后崩溃（`0xC0000005`），
而且**崩在 `Arena::reset()` 函数入口与第一条 printf 之间** —— 连函数体都没进去。
随机策略基线跑 200 局却完全正常。

### 我一开始的错误判断

怀疑自己刚抽的 `rl::Trainer`，查了很多轮没找到。
**这个方向是错的** —— 根因在一个和 Trainer 无关的地方。

### 根因

```cpp
constexpr int MAX_ZONES = 8;
for (int i = 0; i < MAX_ZONES; ++i) {      // ← 错在这里
    const int base = 20 + i * 3;
    if (i < n) { obs[base+0..2] = ...; }
    else       { obs[base+0..2] = 0,0,1; } // ← 无条件执行
}
```

观测尾部只有 `obs[20..31]` 共 **12 个槽**，每圈 3 维 → **只放得下 4 个圈**。
`i=4..7` 时写到 `obs[32..43]` —— **越界 12 个 double = 96 字节**，
而且 `else` 分支无条件执行 → **每次感知都必踩一次**。

### 为什么时序那么诡异

越界写的是调用方**栈上保存的 XMM 寄存器**（Win64 下 XMM6–XMM15 **非易失**）。
写坏它不改变返回值、不立刻报错，只在"保存→恢复"的接缝处露出来：

- 基线 200 局 + 训练第 0 局：被踩的 96 字节恰好属于没人再读的位置 → 一切照跑
- 某个回合开始：被踩的位置变成返回地址 → `reset()` 一进去就崩

**"越界"和"第几局崩"本来就没有因果关系。**

### ⚠️ 游戏本体也在踩

`NeuralBrain::think()` 用的是同一个函数、同样持有 `double obs[rl::OBS_SIZE]`
—— **游戏里每条神经网络蛇每帧都在踩自己 96 字节栈**。

改一个头文件同时修好三处（`train_probe` / `NeuralBrain` / `EpisodeRunner`）。

### 修法

```cpp
constexpr int ZONE_OBS_SLOTS = (OBS_SIZE - 20) / 3;   // 观测里放得下几个圈
static_assert(ZONE_OBS_SLOTS * 3 == OBS_SIZE - 20, "圈观测必须刚好填满尾部");
for (int i = 0; i < ZONE_OBS_SLOTS; ++i) { ... }
```

**`MAX_ZONES`（世界最多几个圈）与 `ZONE_OBS_SLOTS`（观测里放得下几个圈）是两个概念**，混用就出事。

**已有权重不作废**：网络输入向来只读 `obs[0..31]`，越界那 12 个 double 从未进入 `toInput()`。

### 怎么找到的（方法值得记）

反汇编 `train_probe.cpp.obj` 的 COFF 符号表 + `.pdata`/`.xdata` 得到栈帧布局
（`sub rsp,0x1D0`），定位到 `stepObs` 占 `[rsp+0x90, rsp+0x190)`，
而**偏移 256 处正好是保存的 XMM6/7/8** —— 与越界的 96 字节完全对上。

> **教训**：遇到"函数入口就崩、连第一条语句都执行不到"，
> 不要怀疑逻辑 —— 那是**栈被写坏**的特征，直接去找越界写。

## 3. 抽出三个共用单元（消灭"两份实现"）

做游戏内训练时发现：如果训练逻辑留在 `train_probe.cpp` 里，
游戏内训练必然要另写一套 —— 而项目已经因为"两份实现"栽过两次。

| 单元 | 职责 |
|---|---|
| `rl::Trainer` | 网络怎么更新（**梯度四步顺序只此一份**） |
| `rl::EpisodeRunner` | 一局怎么跑 + 奖励怎么算 |
| `rl::TrainTask` | 训练任务的参数与预设 |
| `rl::Checkpoint` | 权重多版本存档 |

`train_probe.cpp` 从 470 行缩到 278 行，**不再自带世界、不再自带 episode 逻辑、不再自带超参**。

```
[ ] 速度   方向键 漫游   PgUp/PgDn 缩放
S 保存权重   L 加载存档（saves/，可存多版本）
```

**★ 面板上的「奖励构成」和「policy」两栏是调参唯一有用的东西。**
只看总回报分不清是哪个信号在推动学习 —— 这是本轮最实用的一个工具。

### 速度：为什么是「时间预算」而不是「档位」

第一版写成"每渲染帧推进 N 个 tick，N 最高 64"，**有个天花板**：

```
主循环被 vsync 锁在 60 帧/秒  →  64 × 60 = 3840 tick/秒 就到顶了
关掉渲染也快不了 —— 省的是绘制，loop 仍然只有 60 帧
```

改成"每帧跑到用掉预算为止"，实测：

| | 吞吐 |
|---|---|
| 旧（档位 64） | 3 840 ticks/s（x64） |
| 新（吞吐段，渲染开） | ~152 000 ticks/s（**x2538**） |
| 新（吞吐段，渲染关） | ~161 000 ticks/s（**x2686**） |

**42 倍。** 负责人反馈的"降到 400x 就降不动"也修了 ——
低倍速改按"每帧几步"精确控制（原来被 `batch = max(batch,1)` 兜底住了）。

## 5. ★ 这个 bug 暴露了我的坏习惯：用负数哨兵关规则

### 现象

负责人报："**蛇一出生就进入下一局**"。

### 根因

我为了"隔离'会不会饿死'这个变量"，把 `starvationTime` 设成 **`-1.0f`** 当"永不饿死"的哨兵值。
而判定是：

```cpp
if (a.body.getTimeSinceEat() > m_cfg.starvationTime) a.body.die();
//                         0.017 > -1.0   →   恒成立
```

**"永不饿死"实际变成了"第一帧就饿死"。**

### 查了多少弯路

怀疑过出生几何（改了两次）、撞墙、撞自己 ——
最后靠**加死因诊断**（让代码自己说是哪条路杀的）才定位到。

### 修法

负责人一句话点破了：

> "你为什么要设置永不饿死？反正一局时间足够短，不改不就行了？"

**单局 10 秒 < 饥饿 20 秒 → 局内不会饿死是"自然成立"的**，一次也没碰饥饿规则。

并且从根上堵住：`if (m_cfg.starvationTime > 0.0f) { ...整条规则跳过... }`
—— 以后有人再写负数，只会得到"不饿死"，不会得到"立刻死"。

> **教训**：不要用负数/0 当"禁用"标志。
> 每条规则的判定方向不一样，很容易变成反效果，而且现象离原因很远。
> **让条件自然不成立**，或者显式加一个 `enabled` 标志。

## 6. ★ 奖励机制：为什么原来看起来"完全没用"

### 发现一：某项塑形**从不触发**

原来的塑形是"到**视野内最近食物**的距离变化"。但视野只有 1024px，
而食物只在 4 个圈里 —— **蛇不在圈附近时视野里一个食物都没有**，
`foodDist` 直接是 `1e9`，该项**完全不触发**。

于是圈外那段时间唯一的信号是照拿的存活奖励 → **学出来就是苟活，不是觅食**。

改成"到**全图最近的可吃食物**"，信号才全程可用。

### 发现二：`0 0 1` —— 策略坍缩成"永远右转"

`policy` 读数锁死 `0.00 0.00 1.00`。在这个游戏里"永远右转"就是
**绕固定半径的圈原地打转**（转向 8 rad/s ÷ 速度 250 → 半径约 31px）。

**而且这是我自己造的陷阱**，有三层：

1. **差分塑形对闭合回路净和为 0**

   ```
   绕一个闭合回路：d0 → d1 → ... → dn，且 dn = d0
   总和 = k·[(d0−d1) + (d1−d2) + ... + d(n−1)−dn]
        = k·(d0 − dn) = k·0        ← 望远镜求和，中间项全部抵消
   ```

   **所以"绕圈"这个行为，所有塑形项既不奖励也不惩罚**，而存活奖励照拿。

2. **REINFORCE 的结构缺陷**：概率到 `(0,0,1)` 后熵为 0 ——
   采样永远出同一个动作、梯度里 `(onehot − p) ≈ 0`，**坍缩不可逆**。

3. **熵正则拦不住**：`dH/dz = −p(log p + 1)`，p 越小它越小。

   | p | 熵梯度（防守力） |
   |---|---|
   | 0.5 | 0.00153 |
   | 0.01 | 0.00036 |
   | 0.0001 | **0.0000082** |

   而策略梯度还在把 p 推得更小 → **自我强化的坍缩**。

**修法**：加 **ε-greedy**（`explorationEps = 0.05`）—— 探索强度**不随 p 衰减**，
不会被正反馈吃掉。熵正则保留（系数调到 0.1）但注释里写明**别指望它单独阻止坍缩**。

⚠️ **效果未确认** —— 负责人反馈"依旧 0 0 1"。

## 7. 顺着负责人的提问查出来的两件事

### ① "为什么蛇学不会躲避墙？"

**因为墙看得见，但没有躲避的动机。**

| | 有吗 |
|---|---|
| 观测里**看得见**墙 | ✅ `obs[0..7]` 是八个方向的障碍距离 |
| 奖励里**鼓励避开**墙 | ❌ **没有**，只有真撞上才 `-1.0` |

> **看得见 ≠ 有动机避开 —— 这是两件事。**

### ② "蛇只能观察到其它蛇的头部，还是全身？"

查了 `PerceptionBuilder.cpp:169` —— **全身都画进视野网格**，
而且 `obs[0..7]` 的八方向障碍距离把 `CELL_ENEMY_BODY` 和 `CELL_WALL` 一起算作障碍。
**"把墙和敌人身体看作同样的"在观测层面本来就成立。**

### ③ 但危险区的实现是错的，而且正好在**惩罚猎杀**

规则是「**我的头**碰到**对方的身体**才死」，而我量的是**头到头**：

| | |
|---|---|
| 应该量 | 我的头 → 对方**身体** |
| 我量的 | 我的头 → 对方**头** |

后果：包围对手时我的身体必然贴着它，头到头也可能很近 →
**"想包围"和"想活命"被混成了同一个惩罚**。

**修法**（负责人选了"修错 + 显式鼓励包围"）：新增两个**分开算**的感知量
（`Perception.h`）：

```cpp
float headToEnemyBodyDist;    // 我的头 → 对方身体/头   ← 危险
float enemyHeadToMyBodyDist;  // 对方头 → 我的身体      ← 猎杀优势
```

它们是一对反向的量：

| 奖励 | 量 | 符号 |
|---|---|---|
| 危险区 `snake` | 我的头靠近它身体 | **-0.5/帧**（< 60px） |
| 包围 `hunt` | 它的头靠近我身体 | **+0.03 × Δd**（< 250px，差分） |

**两条同时存在时，"用身体别住对手、同时把头让开"是唯一既能拿分又不扣分的做法 —— 那就是包围。**

⚠️ **效果未确认。**

## 8. 训练任务：从"一条蛇"到"分任务"

### 为什么分

"躲墙 / 躲蛇"和"觅食"是两个不同的学习目标，放在同一个任务里互相干扰。
而"最小验证"的目的是**确认学习链路通不通** —— 那是最不该混进额外变量的时候。

### 三个任务

| 任务 | 地图 | 蛇 | 食物 | 一局 | 学什么 |
|---|---|---|---|---|---|
| **食物圈** | 2000×2000 | 3 | 4 圈轮换，0.5 个/秒 | 60 秒 | 觅食 + 躲避 + 猎杀 |
| **食物圈·单圈** | 1200×1200 | 1 | 1 个居中的圈，r=216px | 15 秒 | "待在圈里就有吃的" |
| **正前方食物（无圈）** | 2000×2000 | 1 | 正前方一串，吃掉后重放 | 10 秒 | 链路通不通 |

### 角色表取代 `snakes` 字段

原来 `snakes`（几条）和"谁是学习的那条"是**两个信息源**，容易对不上。
现在只有 `roles` 一个来源：

```cpp
enum class AgentRole { Learner, Dodge, Hunt, Rule };
int snakeCount() const { return static_cast<int>(roles.size()); }
```

**陪练用规则 AI 而不是也让它学** —— 对手行为固定，学到的策略才可归因。

### ⚠️ 一处命名踩的坑

第一版叫"食物圈小测试"和"朝前觅食（最小验证）"，
**"小测试"和"最小验证"太像了**，而真正区分它们的**"有没有圈"反而没写出来**。
负责人因此在"朝前觅食"里找了半天食物圈。

改成把差别写进名字：`食物圈（4 圈轮换 + 3 蛇）` / `食物圈·单圈（1 圈 + 1 蛇）` /
`正前方食物（无圈）`。

> **教训**：给"最小验证/小测试"这类东西命名时，
> 名字里要写**它和其它任务最本质的差别**，而不是"它是小的那个"。

## 9. 权重多版本存档

负责人问："每次我点开训练模式，训练的矩阵参数会保存吗？
我希望我能手动选择保存，并且可以加载多个版本的矩阵。"

**先回答：以前不会。** 进训练模式每次都用固定种子重新初始化网络，练到一半退出就全没了。

现在：`S` 保存、`L` 打开列表加载。文件名带**局数 + 时间戳**：

```
saves/ep000123_20260923_091530.txt
```

**为什么带这些** —— "多版本"的关键是**能分辨哪个是哪个**。
只存 `latest.txt` 的话第二次就覆盖了，等于没有多版本。

⚠️ **加载权重后自动重置基线**：基线是"最近回报的滑动平均"，
属于**这次训练的过程状态**，不在权重里。不重置的话新策略会拿**旧策略**的基线算
advantage，现象是"加载完反而变笨了一阵"。

## 10. 沿路修掉的小 bug

| 现象 | 根因 | 修法 |
|---|---|---|
| 重开一局**尸体不消失** | `Arena::reset()` 清了蛇但**没清食物**（抽 `Arena` 时的回归：以前 `GameScene` 是整个重建 `FoodManager`） | 新增 `FoodManager::reset()` |
| 小地图上 400 图一出界 | `spawnRadius = mapMin*0.32` 在 400 图上只留 72px 到墙 | 改成"至少留 100px 余量"，并核对 2000² 上值不变 |
| 出生范围退化成一个点 | `spawnMargin = 200` 写死，400 图 → 范围 `[200,200]` | 改成"地图短边的 15%"，同样核对 2000² 不变 |
| **面板文字全叠在一起** | `line()` 助手一路累加 y 到约 380，而后面的状态提示**把 y 硬设回 320** | 改成分节常量 `SECTION_*`，每节固定起点 |
| 改蛇数会清空训练进度 | 绑在按键 `1/2/3` 上，会重建世界 | 环境参数全部前置到 `TrainSetupScene` |
| 食物圈只有 1 个食物 | 定点食物的重放逻辑只在"吃掉之后"触发，而且没在食物圈任务里启用 | 加"食物圈·单圈"任务 |
| 朝前觅食"会朝食物前进但撞墙" | 食物距离 300 而出生边距只有 60 → 食物**被夹进地图内**，方向和距离都变了 | 地图 2000²、居中出生、加硬约束"出生边距 >= 食物距离 + 余量" |

## 11. 方法上的收获（写给下一个人）

1. **"函数入口就崩" = 栈被写坏**，去找越界写，不要审逻辑
2. **不要用负数哨兵关规则**
3. **调参必须有判据** —— 面板的「奖励构成」就是判据；某项恒为 `0.00` 说明它从不触发
4. **差分的塑形对"绕圈"无效**（闭合回路净和为 0）
5. **现象伪装成逻辑错误时，先查配置和打印** —— 本轮好几个 bug 都不是逻辑错误
6. **带调试探针的二进制，跑出来的数字不能当结论**
7. **"看得见 ≠ 有动机"** —— 观测里有某个信息，不等于策略会用它
8. **验证状态要如实写** —— 含糊其辞比不写更糟
