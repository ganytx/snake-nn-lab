## 0. 目标与已定决策

**目标**：把蛇分成若干队（可以是不同算法），让它们互相对抗，学习生存 / 捕猎 / 合作；
用户能在游戏里选算法、直接比较。

已定决策（本轮拍板）：

| 决策点 | 结论 |
|--------|------|
| 感知粒度 | **只给原始感知**（实体 + 相对坐标），编码成网络输入完全由算法负责 |
| 视野规则 | **可配置**，默认固定半径 |
| 队友可见性 | 配置项 `teamAwareness`，**默认开启**；只给队友头位置与长度，不给体节 |
| 队友碰撞 | **不碰撞、可穿过** |
| 第一步 | 修底座 → 接口 → 规则AI迁移 → 实验场观战 |

## 1. 分层架构

```
┌───────────────────────────────────────────────────────────┐
│  算法层  src/brain/                                        │
│    Brain（抽象基类）· RuleBrain · NeuralBrain · 用户自定义   │
│    ★ 只依赖 Perception / Action，不认识 Snake、GameScene     │
│    ★ 不依赖 SFML（所以不能被 #include <SFML/...>）           │
└──────────────▲────────────────────────┬───────────────────┘
               │ Perception              │ Action
┌──────────────┴────────────────────────▼───────────────────┐
│  智能体层  src/agent/                                      │
│    Agent = 一条蛇 + 一个 Brain + 感知缓冲                    │
│    职责：算视野（走空间网格）、填 Perception、施加 Action    │
└──────────────▲────────────────────────┬───────────────────┘
               │ 世界查询                │ 转向/加速
┌──────────────┴────────────────────────▼───────────────────┐
│  仿真层  src/sim/                                          │
│    World：Snake / Food / SpatialGrid / 碰撞 / 生死 / 统一Rng │
│    ★ 不知道"AI"这个概念，只认"转向意图 + 加速开关"           │
└───────────────────────────────────────────────────────────┘
```

**分离的验收判据**：把 `src/brain/` 整个删掉，`src/sim/` 必须照样能编译通过。

**为什么算法层不允许依赖 SFML**：一是无头训练模式下完全不初始化窗口/图形上下文，
二是防止有人偷偷用 `sf::Vector2f` 把两层的类型系统黏在一起。
所以算法层用自己的 `arena::Vec2`（就是两个 float），智能体层负责与 `sf::Vector2f` 互转。

## 2. 感知接口 `Perception`

设计原则：**受限 · 相对 · 有序 · 无分配**

**接口的核心是「视野网格」**：游戏把蛇头周围一定范围光栅化成一张固定尺寸的格子图，
每个格子用位掩码标记"这里有什么"。**算法自己决定怎么用这张图**——
可以直接拍平喂网络，也可以先从里面提取出食物/敌人的位置、组成一个小向量再喂网络。

> 这个分工是有意的：网格是**感知**（像视网膜），"该注意什么、怎么编码"是**算法**。
> 分辨"这格是食物还是敌人"不算越界——那和视网膜分辨颜色是一回事。

### 2.1 视野网格 `VisionGrid`

```cpp
namespace arena {

// 每格 1 字节位掩码。一格里有多种东西也能同时表达，不像"单值类别"要定优先级。
//   0x01 墙 / 地图边界
//   0x02 普通食物
//   0x04 尸体食物（更值钱，也说明附近刚死过蛇）
//   0x08 敌方蛇身
//   0x10 敌方蛇头
//   0x20 队友蛇身
//   0x40 队友蛇头
//   0x80 自己身体
constexpr std::uint8_t CELL_WALL      = 0x01;
constexpr std::uint8_t CELL_FOOD      = 0x02;
constexpr std::uint8_t CELL_CORPSE    = 0x04;
constexpr std::uint8_t CELL_ENEMY_BODY= 0x08;
constexpr std::uint8_t CELL_ENEMY_HEAD= 0x10;
constexpr std::uint8_t CELL_ALLY_BODY = 0x20;
constexpr std::uint8_t CELL_ALLY_HEAD = 0x40;
constexpr std::uint8_t CELL_SELF_BODY = 0x80;

// 网格固定 32 x 32 格；格边长由对局配置给出。
//   cellSize = 32px  →  视野 1024 x 1024px，位置精度 ±16px
//   32px = 蛇身直径，一格正好装下一条蛇身
//
// 精度够不够？位置误差 ±16px，而蛇的转向半径只有 v/ω = 250/8 = 31px，
// 所以在误差范围内蛇依然来得及转向。
//
// ★ 为什么格数是 32 而不是 50？
//   光栅化成本 = 格数 x 每格约 10 次运算，**与格边长无关**。
//   缩小格边长只缩小视野，格数不变、成本一分不降。
//   真正有效的杠杆是减少格数：50x50 = 2500 → 32x32 = 1024（成本降到 41%）。
//   视野随之从 2400px 降到 1024px，在地图 2000x2000 上约占一半，
//   从"看得见整张图"变成"只看得见自己周围"，博弈也更真实。
constexpr int VISION_COLS = 32;
constexpr int VISION_ROWS = 32;

struct VisionGrid {
    std::uint8_t cells[VISION_ROWS][VISION_COLS];

    // 网格中心 = 蛇头所在格；网格整体【随蛇头朝向旋转】——
    // 也就是"前方永远朝上"。见下面的说明，这是本设计最重要的一条。
    int centerRow = VISION_ROWS / 2;
    int centerCol = VISION_COLS / 2;

    // 格子 (r, c) 相对蛇头的世界坐标偏移（已经过朝向旋转）
    Vec2 cellOffset(int r, int c, float cellSize) const;
};
}
```

### 2.2 ★ 网格随朝向旋转（最重要的一条）

网格**不是世界轴对齐的，而是以蛇头朝向为"上"**：

```
        前方
         ↑
   ┌───────────────┐
   │  ·  ·  ·  ·  ·│
   │  ·  ·  ·  ·  ·│
   │  ·  ·  ●  ·  ·│   ● = 蛇头（网格中心）
   │  ·  ·  ·  ·  ·│
   │  ·  ·  ·  ·  ·│
   └───────────────┘
        后方
```

**为什么必须旋转**：神经网络要做的是"左转 / 直行 / 右转"这种**相对自身**的决策。
如果网格是世界轴对齐的，同样的场景出现在东边和北边会落在网格的不同位置，
网络必须额外学会"旋转不变性"——白白浪费容量，而且极难学。

旋转之后，"左边有障碍"永远出现在网格的同一片区域，网络看到的是一个**固定模式**，
学习难度直接降一个数量级。这是能显著影响训练成败的一条。

代价：光栅化时要多做一次旋转（每个实体的相对坐标乘一个 2×2 旋转矩阵），
比世界轴对齐多几次乘加，可以忽略。

### 2.3 其余感知字段

```cpp
struct Perception {
    SelfState self;              // 自身状态（见下）

    // 世界常量："地图多大"算常识，所有蛇都知道，不算作弊
    float mapWidth = 0, mapHeight = 0;

    VisionGrid grid;             // ★ 视野网格（随朝向旋转，见 2.2）
    float cellSize   = 32.0f;    // 每格边长（像素）
    bool  teamAware  = false;    // 本局是否开启队友全局感知
    int   tick = 0;
    float dt   = 0.0f;

    // 队友可见性：接口提供【最近的 N 个队友】，N 由设置项配置，默认 2。
    // 实际数量可能少于 N（队友总数不够，或者只有这么多个还活着）。
    //
    // 为什么不放进网格里？因为网格只有 2400px 视野，视野外的队友完全看不见，
    // 而"合作"的前提是知道队友在哪。所以队友走一条独立的全局通道。
    //
    // 这也正是它值得做成设置项的原因：N 的大小直接决定"合作"有多容易涌现，
    // 这本身就是一个可研究的实验变量。N = 0 即完全关闭队友全局感知。
    std::vector<VisibleSnake> allies;   // 按距离由近到远，最多 allyVisibleCount 个
};

struct SelfState {
    int   id = 0, teamId = 0;
    Vec2  pos;                   // 世界坐标
    float heading = 0.0f;        // 绝对朝向（弧度）
    float speed = 0.0f;
    int   length = 0;
    bool  boosting = false;
    float hungerLeft = 0.0f;     // 距离饿死还剩几秒
    float headRadius = 0.0f, bodyRadius = 0.0f;
    bool  alive = true;
};
```

### 2.4 光栅化的几条约定

| 情况 | 处理 | 理由 |
|------|------|------|
| 实体落在哪一格 | 按**圆心**所在格标记 | 体节间距 20px < 格边长 32px，相邻体节必落相邻格，身体不会断开 |
| 视野超出地图边界 | 标记为 `CELL_WALL` | 撞上去会死，必须当成墙 |
| 被其他蛇挡住 | **不做遮挡** | 射线遮挡查询太贵，且对博弈价值有限 |
| 一格里有多种东西 | 位掩码按位或 | 不需要定优先级，信息不丢 |
| 自己身体 | 标记为 `CELL_SELF_BODY` | 本作不检测自撞，但"我的身体堵住了退路"是真实约束 |
| 网格中心格 | **不画自己的头** | 中心格恒亮，无信息量，纯噪声 |

### 2.5 性能与开关

50×50 已被改成 32×32：2500 格 → **1024 格**，每帧要清空 + 重填的字节数降到 41%。
按实测的每秒上万帧算，这是几十 MB/s 的内存写入，可以接受但不算免费。

> ⚠️ 再强调一次：**感知成本和格边长无关，只和格数有关**。
> 想调便宜就减格数；调格边长只影响视野范围与精度。

因此 `BrainInfo` 增加一个开关：

```cpp
bool needsVisionGrid = true;   // 算法用不到网格时可以关掉，省下这份开销
```

智能体层只在算法声明需要时才填网格。这是个"接口诚实"的设计：
不用的算法不该为它付钱。

> 实测数据见 `devlogs/2026-09-21.md` 第五批。**填充网格的真实成本必须实测**，
> 不能拍脑袋——上一轮探针已经证明直觉是不可靠的。

## 3. 动作接口 `Action`

```cpp
namespace arena {

struct Action {
    float steer = 0.0f;   // [-1, +1]：-1 = 满舵左转，0 = 直行，+1 = 满舵右转
    bool  boost = false;
};

enum class ActionSpace {
    Continuous,   // steer 取任意 [-1, 1]
    Discrete3,    // {-1, 0, +1}
    Discrete5,    // {-1, -0.5, 0, +0.5, +1}   ← 默认
    Discrete7
};

// 把任意 steer 规范化到指定动作空间（超范围会被夹取/量化）
float quantizeSteer(float steer, ActionSpace space);
int   actionCount(ActionSpace space);      // 神经网络输出维度用
float steerOfIndex(int index, ActionSpace space);
}
```

### 落到蛇身上的换算

```
目标朝向 = 当前朝向 + steer × turnRate × dt
snake.setTargetAngle(目标朝向)
```

**为什么用相对转向而不是绝对目标角**：绝对角要求网络自己学"我朝哪 / 该朝哪"的关系；
相对角直接就是"往左打多少舵"，对神经网络友好得多，也是标准做法。
同时它**保留了蛇现有的缓动转向手感**——满舵时约 10 个 tick（1/6 秒）加速到最大角速度，
因为在缓动模型下 `maxTurn` 与 `steer` 在稳态是线性的。

### 为什么动作空间是对局级配置

**为了公平**。现在的规则 AI 输出连续角度；如果神经网络只能出 3 个离散动作，
规则 AI 就白占了便宜，"哪个算法强"的结论不成立。
同一场对局里所有算法必须使用同一个 `ActionSpace`。

**默认取 `Discrete5`**：因为本项目的主线是比较算法，默认值应该是"公平的那个"。
规则 AI 通过把目标角差量化到最近档位来适配。想恢复原来的连续手感，改一行配置即可。

## 4. 算法接口 `Brain`

```cpp
namespace arena {

struct BrainInfo {
    std::string id;            // "rule" / "nn-survivor"，UI 与存档只认它
    std::string displayName;   // 界面上显示的名字
    std::string description;
    bool needsWeights = false; // 是否需要加载权重文件
    bool trainable    = false; // 是否参与学习
};

class Brain {
public:
    virtual ~Brain() = default;
    virtual const BrainInfo& info() const = 0;

    // ★ 唯一必须实现的方法：看感知，出动作
    virtual Action think(const Perception& p) = 0;

    // 生命周期钩子（按需重写；神经网络用来清理回合状态）
    virtual void onEpisodeStart(uint32_t seed) {}
    virtual void onDeath() {}
    virtual void onEpisodeEnd(double teamReward) {}

    // 训练钩子：智能体层把这一步的经验交回算法，学不学由算法自己决定
    virtual void observeStep(const Perception& p, const Action& a, double reward) {}

    virtual void onMatchEnd() {}
    virtual bool isTrainable() const { return info().trainable; }
};
}
```

### Brain 实例的生命周期

**per-snake 实例 + 共享模型**：同队每条蛇各持有一个 `Brain` 对象
（这样每条蛇可以有独立记忆状态，将来上 RNN 不用改架构），
但内部网络权重通过 `std::shared_ptr<Model>` 共享。

### 智能体的两个额外职责

`Agent` 除了持有 `Brain`，还要负责：

1. **高频感知更新与低频决策解耦**。感知每 tick 更新（碰撞规避需要新鲜数据），
   但决策可以按 `reactionTime` 节流——现有规则 AI 已有这个机制，
   神经网络也可以配置决策频率。这既省算力，也模拟生物反应延迟。
2. **把 `Action` 翻译成蛇的调用**，并做合法性校验（`quantizeSteer` + 夹取）。

## 5. 算法注册表

```cpp
class BrainRegistry {
public:
    static BrainRegistry& instance();

    void reg(const BrainInfo& info, std::function<std::unique_ptr<Brain>()> factory);

    const std::vector<BrainInfo>& list() const;
    bool has(const std::string& id) const;
    std::unique_ptr<Brain> create(const std::string& id) const;

    // 需要额外参数的算法（如神经网络要加载权重）
    std::unique_ptr<Brain> createWithWeights(const std::string& id,
                                             const std::string& weightsPath) const;
};

// 在 main() 里显式调用一次，注册所有内置算法
void registerBuiltinBrains();
```

**为什么用显式注册函数而不是静态初始化宏**：初学者友好、断点好下、
注册顺序可控、不会踩"静态初始化顺序"的坑。

UI 只认 `list()` 返回的 `BrainInfo`，所以**新增算法不需要改任何 UI 代码**。

## 6. 训练场地（Arena）

```cpp
struct TeamConfig {
    std::string name;         // "红队"
    std::string brainId;      // "rule" / "nn"
    std::string weightsPath;  // 神经网络权重路径，可为空
    int         memberCount = 1;
    uint32_t    color = 0xFFFFFFFF;
    float       spawnAngle = 0;   // 出生的方位角（各队均分圆周）
};

struct ArenaConfig {
    uint32_t    seed = 0;          // ★ 确定性：同种子必须跑出完全相同的一局
    int         mapW = 8000, mapH = 8000;
    ActionSpace actionSpace = ActionSpace::Discrete5;
    float       viewRadius = 600.0f;
    bool        teamAwareness = true;
    bool        friendlyFire = false;   // 队友不碰撞
    int         tickLimit = 60 * 120;   // 限时制：2 分钟
    std::vector<TeamConfig> teams;
};

struct MatchResult {
    uint32_t seed = 0;
    int      ticks = 0;
    struct TeamStat {
        std::string name;
        double avgSurvival = 0;   // 平均存活 tick
        double avgLength = 0;     // 结束时平均长度
        int    kills = 0, deaths = 0;
        double score = 0;
    };
    std::vector<TeamStat> teams;
};
```

### 胜负判定：限时制 + 综合分

```
队伍分 = Σ(成员最终长度) + 3 × 队伍总击杀
```

**不用"最后存活"**：长局采样效率太低，跑分要几百局才有统计意义。
限时制每局时长固定，便于批量跑分和对比曲线。

### 队伍出生

各队出生方位均分圆周（`spawnAngle = 2π × i / teamCount`），
避免所有队一开始就挤在中心互相撞死——那样学不到"合作"，只学到"乱斗"。

### 三种运行模式

| 模式 | 渲染 | 用途 |
|------|------|------|
| **观战** | ✅ 窗口 | 在游戏里选算法开局对抗，直接看表现 |
| **跑分** | ❌ 无头 | 同配置跑 N 局，输出 CSV，算均值/方差 |
| **训练** | ❌ 无头 | 指定某队为可学习算法，其余队当陪练 |

## 7. 必须先修好的底座

| # | 问题 | 为什么是前置条件 |
|---|------|-----------------|
| B1 | 全局 `rand()` 满天飞 | 没有统一种子 → 跑分不可复现，"哪个算法强"就是噪声 |
| B2 | 碰撞与感知是 O(n²) | 每条蛇每 tick 都要"看"周围，不建空间网格无头训练跑不快 |
| B3 | `AIController` 非多态，且与两个平行容器按索引绑死（缺陷 #11） | 加 `Brain` 前必须重构成 `vector<unique_ptr<Agent>>` |
| B4 | 加速不消耗体节（缺陷 #21） | 团队对抗里若不付代价，最优策略是永久加速，比较失去意义 |
| B5 | 没有回放/记录 | 训练出问题时要能回答"它为什么死在这里" |

## 8. 实施路线（每步都能独立验证）

| 步 | 内容 | 验收标准 |
|----|------|---------|
| **F1** | `docs/40` 定稿 + `src/brain/` 接口头文件 | 编译通过；删掉整个 `src/brain/` 后仿真层仍可编译 |
| **F2** | 统一 `Rng`，替换所有 `rand()` / `Math::randomFloat` | 同一 seed 连跑两局，逐 tick 状态完全一致 |
| **F3** | `SpatialGrid` 空间网格，替换碰撞与感知的全量遍历 | tick 速率提升；碰撞行为与原来一致 |
| **F4** | `BrainRegistry` + `RuleBrain` 迁移 | 旧的规则 AI 行为在 `Continuous` 动作空间下与迁移前一致 |
| **F5** | `Agent` + `World` 重构，`GameScene` 改为持有 Agent | 游戏可正常运行，AI 行为不变 |
