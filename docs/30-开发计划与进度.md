### ★ 排查训练问题的方法论（血泪换来的，请沿用）

本轮花了大量轮次在"调参 → 看不出效果 → 再调"的循环里。**教训：**

1. **不要用哨兵值关掉一条规则。**
   本轮把 `starvationTime` 设成 `-1.0f` 当"永不饿死"，而判定是
   `timeSinceEat > starvationTime` —— 负数让它**恒成立**，
   "永不饿死"实际变成"第一帧就饿死"。查了好几轮才定位。
   **想让规则不触发，就让条件自然不成立**（比如把单局时长设得比饥饿短）。

2. **调参前先想清判据。**
   训练面板的「奖励构成」和「policy」两栏就是判据工具：
   - 某个分量恒为 `0.00` → 它**从不触发**（"视野内食物塑形"曾经就是这样，
     因为食物只在圈里，而蛇不在圈附近时视野里什么都没有）
   - `policy` 三项都 ≈ 0.33 → 策略**什么都没学到**
   - `policy` 锁死 `0 0 1` → 策略**坍缩**成"永远右转"（绕固定半径的圈打转）

3. **差分的塑形项对"绕圈"无效。**
   `k·(前一步距离 − 这一步距离)` 在闭合回路上**总和恒为 0** ——
   所以绕圈时塑形既不奖励也不惩罚，而存活奖励照拿，于是绕圈成了稳定的局部最优。
   （推导见 [docs/80](80-训练可视化.md) 第 1.5 节）

4. **现象伪装成逻辑错误时，先查配置和打印。**
   本轮有好几个 bug（配置值不一致、`printf` 格式串、调试探针污染数据）
   **都不是逻辑错误**，但现象都像"核心逻辑坏了"。

5. **带调试探针的二进制，跑出来的数字不能当结论。**
   本轮曾据此误判"编码改坏了"，清理探针后重跑三次结果完全一致。

6. **"函数入口就崩、连第一条语句都执行不到" = 栈被写坏。**
   不要怀疑逻辑，直接去找越界写。本轮那个 96 字节越界写就是这样定位的
   （反汇编 + 栈帧分析，见第 6 节 #35）。

### ★★ 2026-09-27 再追加：预告圈的【出现时机】改为"供食还剩 3s"

> 负责人规格："不要一开始就有预告圈，预告圈是在活跃圈产食物**还剩 3s** 后出现的，
> 然后中间有一定时间 gap，然后再被激活。"

```
 0s ───────────── 6s ────────── 9s ───────── 14s ────────── 23s
 │←── 只有活跃圈 ──→│←──── 预告期 ────→│←─ 空窗 ─→│← 新活跃圈供食 ─→
                     ↑ 预告圈出现（spawnDuration − previewLead = 6s）
```

预告圈从出现到被激活共 **8 秒**（3 + 5），而圈间距 600~900px 按 250px/s
要跑 2.4~3.6 秒 ⇒ 余量充足。

`v.visible = v.active || world.zonePreviewing`；三处渲染同步改用 `previewing`。

> ⚠️ `|| v.active` **不能省** —— 少了它，供食期前 6 秒连**当前圈**都会被藏掉。

### ★★ 2026-09-27 再追加：每局换一个世界种子

> 负责人要求："训练模式，游戏模式请每局种子不同。"

**改前的问题**（两处都 `spawnSeed = 0`，而 `Arena::reset` 只在非 0 时播种）：

1. 出生点 / 出生角度 / 食物走全局 `rand()` ⇒ 那是**一条跨局连续的流**，
   重开一局时**不重新随机**；
2. 圈的种子（`orderSeed` / `posSeed`）取自**固定的** `t.seed`
   ⇒ **很多局的圈位序列一模一样**（负责人报过的"固定那两个同样的位置"）。

**改法**：新增 `ArenaConfig::advanceSeedOnReset`

| 取值 | 行为 | 谁用 |
|---|---|---|
| `false`（默认） | 每次 reset 都用同一个 `spawnSeed` | **回归工具**（可复现性） |
| `true` | `seed = spawnSeed + resetCount`，每局换一个 | **训练 / 游戏** |

**世界种子在 `Arena::reset` 一处统一播种**，同时驱动**四处**随机源：
出生点/角度、食物位置（全局 `rand()`）、圈轮换顺序 `orderSeed`、圈坐标 `posSeed`。
—— 它们必须同源，否则"同一局可复现"在调试时就不成立。

**种子仍是可复现的起点**：第 k 局种子 = `spawnSeed + k` ⇒ 同一任务种子的
"第 k 局"永远相同，**对照实验仍可比**，只是每局不再重复。

**验证（训练模式，新增日志）**：

```
  [种子] 第 1 局世界种子 = 20261122
  [种子] 第 2 局世界种子 = 20261123
  [种子] 第 3 局世界种子 = 20261124
```

**回归**：编译 5/5 · `nn_selftest` 6/6 · `replay_check` 逐字节一致
（**故意没变** —— 它不设 `spawnSeed`，走"完全不碰种子"的老分支）·
标墙对拍通过 · 观测仍 33 维。

详见 [devlogs/2026-09-27.md](../devlogs/2026-09-27.md) 第 27 节。

> ★★★ **#48 才是"越训越差"的答案，我最初答错了方向。**
>
> 我最初的判断是"奖励标定错了 3 倍，所以觅食是亏的"。**负责人当场驳回了这个解释，
> 而且驳得对**：
> > "哪怕蛇是随机乱动最后一头撞死也比原地绕圈得到的 reward 更高！
> >  最开始完全没有训练的时候，reward 至少是正的，结果越训练 reward 越小，
> >  直到变成负数，其中完全是原地旋转扣的分。"
>
> **"奖励标定错 3 倍"解释不了"越训越差"** —— 标定错会让所有策略的分数等比缩小，
> 但不会让策略**单调变坏**，更不会让未训练的网络比训练过的更好。
> 那是一个"策略被主动训坏"的特征，只有**方向错误的梯度项**才能造成。
>
> **熵项符号反转正好符合这个特征**：它是唯一一个"不含任务信息、
> 却每局都朝确定化方向推"的项。策略越确定它越大 → 正反馈 → 单调坍缩。
>
> ★ 教训（写给自己）：**"某个常数算错了"只能解释"水平不对"，
> 不能解释"趋势不对"。看到"越训越差"，第一反应该是去找
> "哪一项梯度在系统性地推策略"，而不是去调奖励数值。**

**★ 把奖励换算成「秒」（这是本次最有价值的表）：**

| 项 | 折算 |
|---|---|
| `hunger` 封顶 / `disp` 触发 | 各 **−3.0/秒** |
| 饿着 + 原地转圈（叠加） | **−6.0/秒** |
| 吃一个食物（**修正前**） | +1.0 → **买回 0.17 秒** ❌ |
| 吃一个食物（**修正后**） | +3.0 → **买回 0.5 秒** ✅ |

> **修正前，蛇必须每 0.17 秒吃到一个食物才刚好不亏，而食物生成间隔是 0.5 秒
> —— 也就是说"饿着转圈"在算术上稳赢，"去找吃的"稳亏。**
> 所以"顶着惩罚原地转圈"**不是神经网络学不会，是奖励把正确答案定义成了错的。**
> 这也解释了为什么此前所有调参（lr / 梯度裁剪 / critic / 局时长）都没用：
> **它们都在一个算错了 3 倍的奖励上做实验。**

**不是 actor 有没有变好**。0.3→0.5 是真进步，但下一步不该继续优化 critic。

> `run.bat` 用 `start` 启动，`start` 会把工作目录设成 exe 所在目录，所以游戏在 `build\` 下跑。
> 项目根的 `config/settings.cfg` 是**模板**，构建时被拷进 `build\config\`。
> 想改默认值 → 改根目录那份再 `build.bat`；只想试参数 → 直接改 `build\config\` 或游戏内设置界面。

## 5. 现在能跑什么 / 不能跑什么

### ✅ 已验证可用

| | 验证方式 / 实测 |
|---|---|
| MLP 反向传播正确性 | `nn_selftest` 数值梯度检查，最大相对误差 **9.06e-10** |
| 空间网格标墙正确性 | `bench_sim` 启动时自动对拍 **400 例 × 409600 格全一致** |
| 碰撞加速效果 | 重负载提速 **1.6~2.4×** |
| 训练链路有效性 | `train_probe`：回报 3.79 → **13.11**，死亡率 100% → **40%** |
| 训练速度 | **2000 局 / 18 秒**（≈110 局/秒，单线程） |
| 游戏本体 | 3 队对抗、对局设置、观战、小地图、结算 |

### ⚠️ 已知不足

| | 说明 |
|---|---|
| ★★★ **AI 仍然学不会觅食** | **这是当前唯一的核心问题。** 所有框架/观测/奖励工作都是为了让它可调试，但目标本身没达成。见下面几行的具体表现 |
| 神经网络偏"苟活" | 存活奖励曾远大于吃食物的收益。2026-09-23 已把 `rAlive` 从 `0.01` 降到 `0.002`，但**尚未验证是否改善** |
| ⚠️ **策略会坍缩成"永远右转"** | `policy` 读数锁死 `0 0 1` → 蛇绕固定半径的圈原地打转。**根因之一已知**：差分塑形对闭合回路净和为 0，所以绕圈**既不奖励也不惩罚**，而存活奖励照拿 → 稳定的局部最优。已加 ε-greedy 探索（`explorationEps = 0.05`），**效果未确认** |
| ⚠️ **"视野内食物塑形"从不触发** | 视野 1024px，食物只在圈里；蛇不在圈附近时视野里空无一物 → 该项恒为 0。已用"到最近可吃食物"的全局塑形替代 |
| 神经网络**不会躲蛇** | 训练默认单蛇（为隔离变量）。观测里**有**敌方全身（视野网格 + 八方向障碍距离把敌方身体算作障碍），但**奖励里一直没有"别靠近"的动机** —— 2026-09-23 已加墙/蛇危险区重罚 + 包围奖励，**效果未确认** |
| ⚠️ `replay_check` 本轮未跑 | 本轮动过 `Arena::reset()` / `Arena::step()`，按铁律必须跑。**接手后请优先补跑** |
| 训练不并行 | 单线程，6 核没用上（潜在 6× ） |
| **感知占每帧 55~66%** | 当前头号性能瓶颈，且感知仍是**全量遍历**（没走空间网格） |
| 游戏侧 RNG 仍是全局 `rand()` | 同一 seed 无法复现同一局（`Arena` 已支持 `spawnSeed`，游戏侧还没接） |
| 无头跑分 + CSV（F8）未做 | `Arena` 已抽出，但**限时/胜负/结算仍留在 `GameScene`**，所以"完整对局"还不能无头跑 |

## 8. 文档维护约定

- 改动**行为或设计**前，先更新对应文档，再改代码
- 每完成一步：更新本文的进度表 / 缺陷清单 + 写当天 `devlogs/YYYY-MM-DD.md`
- 缺陷清单**只增不改**，已修的把状态改为 `✅ 已修`
- **改动 `src/nn/` 后必须跑 `build\nn_selftest.exe`**，6 项全绿才算完成
- **改动标墙逻辑后必须看 `bench_sim` 的对拍结果**
- **改动 `Arena` / `FoodManager` / 出生几何后必须跑 `replay_check`**（manual vs arena 逐字节一致）
- **改动 `src/rl/encoder.h` 后，之前训练的权重全部作废**（编码变了网络输入就变了）
- ⚠️ **验证状态要如实写**：跑了什么就写什么，没跑就写"未跑"。
  含糊其辞会让接手的人误以为验证过了 —— 这比不写更糟。
