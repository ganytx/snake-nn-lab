**★ 训练和游戏共用 `src/rl/encoder.h` 里的同一个编码函数。**
这是本链路最重要的约束 —— 编码一旦不一致（哪怕只差一个归一化系数），
训练出来的权重接到游戏里就是废的，而且现象极具迷惑性：网络能跑、不报错，
只是行为完全不对。**这个坑实际踩过**（`train_probe` 里曾有一份拷贝，
扇区边界判断的浮点末位差导致观测最大偏差 0.96）。

## 2. 观测编码（`src/rl/encoder.h`，**32 维**）

| 下标 | 含义 | 取值 |
|------|------|------|
| 0..7 | 8 个方向的**障碍距离** | `VisionGrid::rayDistance(d)`，0=贴着，1=通畅 |
| 8..15 | 8 个扇区里**最近食物的距离** | 归一化 `min(1, 像素距离/800)`，无食物 = 1 |
| 16 | 速度 | `speed / 450` |
| 17 | 长度 | `min(1, 体节数 / 60)` |
| 18..19 | 朝向 | `sin(heading)`、`cos(heading)` |
| **20..31** | **4 个食物圈 × 3 维** | 每圈：相对方位的 `sin`/`cos` + 归一化距离 |

网络 `rl::Policy = MLP<double, 32, 3, 1, 32, tanh, dtanh>` —— **1155 个参数**。

### ★ 障碍距离里**包含敌方身体**

`rayDistance` 判的是一条射线上有没有这些位：

```cpp
CELL_WALL | CELL_ENEMY_BODY | CELL_ENEMY_HEAD |
CELL_ALLY_BODY | CELL_SELF_BODY
```

也就是说 **`obs[0..7]` 把"墙"和"敌人身体"当作同一类障碍** ——
这是刻意的（负责人明确要求"把墙和敌人的身体看作是同样的"）。

> ⚠️ **一个曾经的错误结论**：早期文档写过"观测不含对手"，
> **那是错的**。敌方身体确实在障碍距离里。
> 但要注意区分两件事：
> - **看得见**（观测里有）✅
> - **有动机避开**（奖励里有）❌ —— 这个到 2026-09-23 才补上
>
> **看得见 ≠ 有动机。这是两件事。**

### ★ 4 个圈是硬上限

```cpp
constexpr int ZONE_OBS_SLOTS = (OBS_SIZE - 20) / 3;   // = 4
static_assert(ZONE_OBS_SLOTS * 3 == OBS_SIZE - 20, "圈观测必须刚好填满尾部");
```

`MAX_ZONES`（世界最多几个圈，=8）与 `ZONE_OBS_SLOTS`（观测里放得下几个圈，=4）
是**两个不同的概念**。

> ⚠️ **这里出过一个 96 字节的越界写**：第一版循环上界误用了 `MAX_ZONES`，
> 于是 `i=4..7` 时写到 `obs[32..43]` —— 每次感知都往调用方**栈上**踩 96 字节，
> 写坏非易失 XMM 寄存器。**游戏本体每帧也在踩**。
> 症状是"函数入口就崩、连第一条 printf 都执行不到"，极难查。
> 详见 `devlogs/2026-09-23.md` 第 2 节。

**扇区算法**（用整数判定，不用浮点 `atan2` 取整 —— 那曾经导致两份实现分叉）：

```cpp
// 行是"前"，列是"右"
int foodSector(int dr, int dc);   // 精确整数扇区
```

## 3. 动作空间

训练只用 **3 个动作**（`ActionSpace::Discrete3`）：

| 下标 | 含义 | steer |
|------|------|-------|
| 0 | 左转 | −1 |
| 1 | 直行 | 0 |
| 2 | 右转 | +1 |

**没有加速。** 所以 `NeuralBrain` 也永远返回 `boost = false`。

动作 → 蛇的换算：

```cpp
目标朝向 = 当前朝向 + body.getSteerLead(steer, dt)
```

> ⚠️ **必须用 `Snake::getSteerLead()`，不能写 `steer × turnRate × dt`。**
> 蛇的转向是缓动的，每 tick 只闭合到目标的 `ease` 倍。
> 少了那个因子，实际角速度只有设定值的 1/10。
> 这个 bug 实际发生过（见 `devlogs/2026-09-21.md` 第十四批）。

## 4. ★ 奖励设计（`src/rl/TrainTask.h` 的 `TaskConfig`）

> ⚠️⚠️ **本节描述的 8 项旧奖励已于 2026-09-24 被【整体删除并重写】。**
> **当前生效的规格以 [docs/90-奖励机制.md](90-奖励机制.md) 为准**（只有 5 项）。
>
> **为什么废掉旧的**（完整数据见 docs/90）：
>   1. 总回报里 **99.66% 来自一个哨兵值 bug**（`sqrt(1e9)=31622.8` 混进了差分）
>   2. 六项塑形全是差分，**整局望远镜求和只剩"首末距离之差"**，中间路径全抵消
>   3. "吃掉最近食物"会让目标切换到更远的食物 → 距离跳变 → 差分大负数
>      → **吃食物净收益为负**
>   4. 死亡只罚 −0.5，而"墙边每帧 −0.5"一秒就 −30 → **撞死成了止损**
>
> 下面保留旧规格仅供对照与追溯，**不要照着它调参**。

### 旧规格（已废弃，2026-09-23 版）

**8 个分量**，每 tick（1/60 秒）结算一次：

| # | 分量 | 参数 | 触发条件 | 含义 |
|---|---|---|---|---|
| ① | 存活 | `rAlive = 0.002` | 每 tick，恒定 | 活着就有 |
| ② | 吃到食物 | `rEat = 1.0` | `getScore()` 变大 | 唯一直接奖励觅食 |
| ③ | 视野内食物塑形 | `rShape = 0.002` | 食物进 1024px 视野时 | 靠近看得见的食物 |
| ④ | 最近可吃食物塑形 | `rZone = 0.02` | **全程** | 靠近最近的吃的 |
| ⑤ | 下一圈塑形 | `rNextZone = 0.008` | 全程 | 提前往下一个食物圈移动 |
| ⑥ | 墙距塑形 | `rWall = 0.02` | 离墙 < `rWallRange=150px` | 离墙变远给正分 |
| ⑦ | **墙危险区** | `rWallDanger = −0.5` | 离墙 < `wallDangerDist=60px` | 贴墙每帧重罚 |
| ⑧ | **蛇危险区** | `rSnakeDanger = −0.5` | 头离敌方身体 < `snakeDangerDist=60px` | 每帧重罚 |
| ⑨ | **包围奖励** | `rHunt = 0.03` | 敌方头离我身体 < `rHuntRange=250px` | 差分，鼓励用身体围住对手 |
| ⑩ | 饥饿塑形 | `rHunger = 0.01` | 剩余 < `hungerWarnSec=5s` | 快饿死时持续掉血 |
| ⑪ | 死亡 | `rDie = −0.5` | `!isAlive()` | |

（编号到 ⑪ 是因为 ⑦⑧⑨⑩ 是后续加的；实际就是 8 个独立机制。）

### ★★ 塑形项为什么全用【差分】

差分 = `系数 × (前一步距离 − 这一步距离)`。三个理由：

1. **符合 potential-based shaping** —— 理论上**不改变最优策略**，只加速学习
2. **"太近就扣分"会造出平坦的局部最优** —— 待在那个半径之外往哪走都一样，
   于是它会**停在原地不动**
3. 差分给的是**方向信号**（"往这边走会变好"），而不只是"现在很糟"

### ⚠️ 但差分有个数学性质必须知道：**绕圈时净和为 0**

```
绕一个闭合回路：d0 → d1 → ... → dn，且 dn = d0

总和 = k·[(d0−d1) + (d1−d2) + ... + d(n−1)−dn]
     = k·(d0 − dn) = k·0        ← 望远镜求和，中间项全部抵消
```

**所以"原地绕圈"这个行为，所有塑形项都不奖励也不惩罚**（而存活奖励照拿）。
实测撞上过：`policy` 锁死 `(0,0,1)` → 蛇永远右转、绕固定半径的圈打转，
**而且它自己没有任何理由出来**。

### ★ 危险区为什么是硬阈值而不是差分

⑥ 用差分（远处慢慢引导），⑦⑧ 用硬阈值（"这里绝对不能待"）。
在 60px 这个尺度上蛇一步只走 4px，差分太小、来不及反应；
硬罚保证"只要在里面就一直掉血"，逼它主动离开。

**"范围小 + 罚得重"是刻意的**：范围大（比如 300px）会让蛇觉得"整张图都危险"，
于是畏畏缩缩不敢动。

### ★ 危险 / 猎杀用的是**两个不同的量**

规则是「**我的头**碰到**对方的身体**才死」，所以：

| 感知字段 | 量 | 用途 |
|---|---|---|
| `headToEnemyBodyDist` | 我的头 → 对方身体/头 | **危险**，扣分 |
| `enemyHeadToMyBodyDist` | 对方头 → 我的身体 | **猎杀优势**，加分 |

> ⚠️ **只用"两蛇中心距"是错的** —— 那会把「我的头靠近它身体」（危险）
> 和「我的身体靠近它头」（猎杀优势）混成同一个惩罚，
> 结果就是**一边想让它躲、一边又惩罚了它包围对手**。
> 这两个量都是 2026-09-23 新增的，定义在 `src/brain/Perception.h`，
> 由 `src/agent/PerceptionBuilder.cpp` 计算（**只在视野内**，队友不算）。

### ★ 探索：ε-greedy 是防坍缩的真正保险

`explorationEps = 0.05` —— 以固定概率随机选动作。

**为什么熵正则不够**：`dH/dz = −p(log p + 1)`，p 越小它越小：

| p | 熵梯度（防守力） |
|---|---|
| 0.5 | 0.00153 |
| 0.01 | 0.00036 |
| 0.0001 | **0.0000082** |

而策略梯度还在把 p 推得更小 → **自我强化的坍缩**。
ε-greedy 的探索强度**不随 p 衰减**，所以能打破那个循环。
（`Trainer::entropyCoef = 0.1` 仍保留，但别指望它单独阻止坍缩。）

## 5. 训练任务（`src/rl/TrainTask.h`）

### 三个任务预设

| 任务 | 地图 | 蛇 | 食物 | 一局 | 学什么 |
|---|---|---|---|---|---|
| **食物圈** | 2000×2000 | 3 | 4 圈轮换，0.5 个/秒 | 60 秒 | 觅食 + 躲避 + 猎杀 |
| **食物圈·单圈** | 1200×1200 | 1 | 1 个居中的圈，r=216px | 15 秒 | "待在圈里就有吃的" |
| **正前方食物（无圈）** | 2000×2000 | 1 | 正前方一串，吃掉后重放 | 10 秒 | 链路通不通 |

### 角色表（取代了原来的 `snakes` 字段）

```cpp
enum class AgentRole { Learner, Dodge, Hunt, Rule };
std::vector<AgentRole> roles = { AgentRole::Learner };
int snakeCount() const { return static_cast<int>(roles.size()); }
```

**只有 `Learner` / `Dodge` / `Hunt` 三种角色算奖励并学习**，`Rule` 是规则 AI 陪练。

> **为什么陪练用规则 AI 而不是也让它学**：对手行为固定，学到的策略才可归因。
> 对手也在变的话，分不清是"我方变强"还是"对方变弱"。

> **为什么用角色表取代一个 `snakes` 整数**：原来"几条蛇"和"谁是学习的那条"
> 是两个信息源，容易对不上（改了蛇数忘了改角色）。现在**角色表的长度就是蛇数**。

## 6. 训练器（`src/rl/Trainer.h`）

### REINFORCE 实现要点

```cpp
// 每局结束，从后往前累加
net.zeroGrad();                                    // ① 清零
double G = 0.0;
for (int t = T-1; t >= 0; --t) {
    G = rewBuf[t] + GAMMA * G;

    // ★ 必须对每个时刻重跑 forward —— 网络的缓存只保存【最后一次】前向
    const auto& logits = net.forward(inputBuf[t]);
    const auto probs = nn::softmax(logits);

    auto g = nn::softmaxCrossEntropyGrad(probs, actBuf[t]);
    g = g * (G - baseline);                        // ★ 减基线降方差

    // ★ 熵正则（防坍缩，但拦不住已经开始的坍缩）
    for (int i = 0; i < ACT_SIZE; ++i)
        if (probs.a[i] > 1e-12)
            g.a[i] += entropyCoef * (-probs.a[i]) * (std::log(probs.a[i]) + 1.0);

    net.backward(g);                               // ② 累加
}
net.scaleGrad(1.0 / T);                            // ③ 平均梯度，别忘
net.step(LR, 0.0);                                 // ④ 更新
```

**三个易错点**：
1. **`forward` 必须逐时刻重跑** —— 缓存只有一份
2. **必须减 baseline** —— 否则所有动作概率一起被抬高，学习信号极弱
3. **必须 `scaleGrad(1/T)`** —— `backward` 是累加语义，忘了就把学习率放大 T 倍

### 评估

训练后用**贪心策略**（`argmax`，不再采样）评估。
**必须和随机策略基线比** —— 没有这个零点，"回报在涨"是没有意义的。

## 7. 推理接入（`src/brain/NeuralBrain`）

```cpp
Action NeuralBrain::think(const Perception& p) {
    double obs[rl::OBS_SIZE];
    rl::encodeObservation(p, obs);                    // ← 和训练同一个函数
    const auto& logits = m_policy.forward(rl::toInput(obs));
    return Action{ rl::steerOfAction(nn::argmax(logits)), false };
}
```

- **显示时用 `argmax`（贪心）**，不采样
- **不加速**（动作空间里没有）

## 8. 权重文件格式

纯文本，`nn::MLP::save/load` 读写，人可以看、可以 diff：

```
# snake-nn-lab MLP v1
IN 32
OUT 3
NHID 1
HW 32
# w_in 32x32
<1024 个数>
# b_in 32
...
```

`load()` 会校验 `IN/OUT/NHID/HW` 和数值总个数，不匹配直接返回 `false`
（**不会**把权重硬塞进错误的形状里）。
所以**改了 `OBS_SIZE` 之后旧存档会加载失败** —— 这是对的，那种权重本来就用不了。

## 9. ★ 当前训练链路的不足（截至 2026-09-23）

| | 说明 |
|---|---|
| ★★★ **AI 仍然没学会觅食** | **这是唯一的核心问题。** 本轮所有工作都是为了让它可调试，目标本身没达成 |
| **策略会坍缩成"永远右转"** | `policy` 锁死 `0 0 1` → 绕圈打转。已加 ε-greedy，**效果未确认** |
| **差分塑形对绕圈无效** | 闭合回路净和为 0（见第 4 节），所以绕圈不亏不赚 |
| **7 项新奖励的效果全部未确认** | 墙危险区 / 蛇危险区 / 包围 / 饥饿塑形都是本轮新加的 |
| **观测不含"圈里有多少食物"** | `FoodZoneView.foodCount` 有了，但**没有进观测** —— 所以蛇分不清"现在是哪个圈在生成"，只能靠圈的距离间接推断 |
| **观测不含对手的相对方位细节** | 敌方身体只在障碍距离里，没有单独的"对手在哪、多远、朝哪"通道 |
| 单线程 | 6 核没用上，潜在 6× |
| 感知占每帧 55~66% | 头号性能瓶颈，且感知仍是**全量遍历**（没走空间网格） |
| 无对手行为多样性 | 陪练是固定规则 AI，学到的是"针对这一种对手"的策略 |

## 10. 调参方法论（血泪换来的，请沿用）

1. **不要用负数哨兵关掉一条规则。**
   本轮把 `starvationTime` 设成 `-1.0f` 想表达"永不饿死"，
   而判定是 `timeSinceEat > starvationTime` → **恒成立 → 第一帧就饿死**。
   查了好几轮。**想让规则不触发，就让条件自然不成立。**

2. **调参前先想清判据。** 训练面板的「奖励构成」和「policy」两栏就是判据工具：
   - 某分量恒为 `0.00` → 它**从不触发**
   - `policy` 三项 ≈ 0.33 → 什么都没学到
   - `policy` 锁死 `0 0 1` → 坍缩

3. **不要只看总回报。** 总回报是 8 个分量的和，涨了也不知道是谁的功劳。

4. **带调试探针的二进制，跑出来的数字不能当结论。**
