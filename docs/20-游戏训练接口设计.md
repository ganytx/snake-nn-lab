## 1. 为什么用 REINFORCE

### 1.1 和监督学习的区别

| | 监督学习 | 强化学习 |
|---|---------|---------|
| 每个样本给什么 | `(输入, 正确输出)` | `(状态, 动作, 奖励)` |
| 谁告诉网络"该输出什么" | 人类标注 | **没人**，只有奖励这个标量 |
| 核心难点 | — | **信用分配**：这一局最后赢了，是前面哪一步的功劳？ |

贪吃蛇里，吃到食物 `+1`，撞墙死亡 `-1`。但你在死亡前 300 帧做的那个转向决策，
可能才是真正的死因。**奖励是延迟的、稀疏的、和动作不同步的**——这就是强化学习要解决的问题。

### 1.2 为什么选 REINFORCE

它是**最基础、最容易手写正确**的策略梯度算法，且和我们已有的
`softmaxCrossEntropyGrad()` 完美契合。相比之下：

- **DQN** 需要目标网络 + 经验回放 + 自举，坑多、难调试
- **Actor-Critic** 需要一个额外的价值网络，概念上更绕
- **进化策略** 不需要反向传播，那就白写了 `backward()`

先用 REINFORCE 把"从奖励里学"这件事跑通，之后要升级到 Actor-Critic 只是加一个价值头的事。

## 2. 观测设计（Observation）

### 2.1 为什么不能把整个游戏世界喂给网络

网络输入是**定长向量**。世界里有几十条蛇、上千个食物，数量还在变。
所以要设计**传感器（sensors）**，把世界压成固定长度的向量——就像给蛇装上眼睛。

### 2.2 传感器方案：射线探测（Ray Casting）

```
                    ↑ 正前方
              \     |     /
               \    |    /         8 条射线，间隔 45°
                \   |   /
                 \  |  /
        ─────────  ●  ─────────  ← 蛇头
                 /  |  \
                /   |   \
               /    |    \
              /     |     \
```

每条射线向前步进探测，记录**最近障碍物的归一化距离**（0 = 贴着，1 = 视野内没有）。

### 2.3 观测向量（共 20 维）

| 段 | 维度 | 含义 |
|----|------|------|
| 障碍距离 | 8 | 8 个方向到最近"墙或蛇身"的距离，`dist / VISION` 归一化到 `[0,1]`，无障碍填 1 |
| 食物距离 | 8 | 8 个方向到最近食物的距离，同样归一化；该方向没有食物填 1 |
| 朝向 | 2 | `sin(角度)`、`cos(角度)`（**不要直接喂弧度**，因为 −π 和 +π 会跳变） |
| 自身状态 | 2 | 当前长度 / 100（裁剪到 1）、饥饿剩余时间 / 饥饿上限 |

```
IN = 20
```

> **为什么障碍和食物用同样的 8 个方向？** 这样网络可以把"这个方向有危险"
> 和"这个方向有食物"在同一组空间位置上做比较，学到"食物 vs 风险"的权衡。

### 2.4 关键实现注意

- **归一化是必须的**：长度、距离这些量级差异很大，不归一化会让训练极不稳定
- **射线探测很贵**：8 条射线 × 每条 N 步，每步都要查"这个点附近有没有蛇身"。
  如果暴力遍历所有蛇的所有体节，headless 训练也快不起来。
  → **必须给蛇身体节建空间网格索引**（见缺陷清单 #6），这也是训练性能的第一瓶颈
- **探测步长**：建议 `VISION = 400px`，步长 25px → 每条射线 16 步

## 3. 动作设计（Action）

### 3.1 离散动作空间（推荐）

连续控制（直接输出转向角度）对 REINFORCE 很难收敛。先用离散动作：

| 动作下标 | 含义 |
|---------|------|
| 0 | 左转 `-TURN_STEP` |
| 1 | 直行 |
| 2 | 右转 `+TURN_STEP` |

```
OUT = 3
```

`TURN_STEP` 建议取 `8° ~ 15°`，每 tick 执行一次。加上蛇本身的转向缓动，
最终呈现出平滑的转弯。

> 想要加速能力就把动作扩成 6 个（3 个转向 × 2 个加速开关），
> 观测和网络结构都不需要改，只是 `OUT` 从 3 变成 6。**第一版建议先做 3 个。**

### 3.2 网络到动作

```cpp
auto logits = policy.forward(obs);          // vec<double, 3>
auto probs  = nn::softmax(logits);          // 概率分布
int action  = 按 probs 采样;                 // 注意：是采样，不是 argmax！
```

**训练时必须采样而不是取 argmax**，否则就没有探索，策略会卡在局部最优。
看 AI 实际表现（推理）时才可以取 `argmax`。

### 3.3 采样怎么实现

```cpp
double r = uniform01();
double acc = 0;
for (int i = 0; i < OUT; ++i) { acc += probs.a[i]; if (r < acc) return i; }
return OUT - 1;   // 浮点误差兜底
```

## 4. 奖励设计（Reward）

奖励设计是强化学习里**最影响成败**、也最需要反复实验的部分。

### 4.1 第一版（建议）

| 事件 | 奖励 | 理由 |
|------|------|------|
| 吃到食物 | `+1.0` | 主目标 |
| 每 tick 存活 | `+0.01` | 鼓励活着，缓解稀疏奖励 |
| 撞墙 / 撞蛇死亡 | `-1.0` | 主惩罚 |
| 靠近食物（距离减少） | `+0.02 × Δ距离` | **塑形奖励**，给早期学习提供方向 |
| 靠近危险（距离减少） | `-0.02 × Δ距离` | 同上 |

> **塑形奖励（reward shaping）** 是让强化学习在稀疏奖励下能启动的关键技巧。
> 但要注意：塑形项太强会让 AI 学会"刷分"而不去真正吃食物（奖励黑客）。
> 建议先只用"吃到食物 + 死亡"，跑不通再加塑形。

### 4.2 为什么用折扣回报

```
G_t = r_t + γ·r_{t+1} + γ²·r_{t+2} + ...
```

`γ`（折扣因子，典型 `0.99`）表示"越久以后的奖励越不值钱"。
它让网络更关注**近期**的后果，也保证级数收敛。

计算顺序是**从后往前**：

```cpp
double G = 0;
for (int t = T - 1; t >= 0; --t) {
    G = rewards[t] + gamma * G;
    returns[t] = G;
}
```

## 5. REINFORCE 算法

### 5.1 直觉

> "如果这一局最后结果不错（`G` 大），那就**提高**这一局里所有动作的概率；
> 结果很差（`G` 小甚至为负），就**降低**它们的概率。"

### 5.2 数学形式

策略梯度定理给出：

```
∇_θ J = E[ ∇_θ log π_θ(a_t | s_t) · G_t ]
```

我们要**最小化**的"损失"就是它的相反数：

```
L = - log π_θ(a_t | s_t) · G_t
```

### 5.3 落到代码上（和 `loss.h` 完美对接）

注意这个关键联系：

```
∂(-log π(a|s)) / ∂logits  ==  softmaxCrossEntropyGrad(probs, a)  ==  probs - onehot(a)
```

而 `G_t` 只是个常数系数。所以：

```cpp
net.zeroGrad();
for (int t = 0; t < T; ++t) {
    auto logits = net.forward(obs[t]);
    auto probs  = nn::softmax(logits);

    // 基础梯度：∂(-log π)/∂logits
    auto g = nn::softmaxCrossEntropyGrad(probs, actions[t]);

    // ★ 用回报加权。注意用 (G - baseline) 降低方差
    const double weight = returns[t] - baseline;
    g = g * weight;

    net.backward(g);
}
net.scaleGrad(1.0 / T);
net.step(lr);
```

**第 4 章学的 `p - onehot` 公式，在这里就是整个算法的核心。**

### 5.4 基线（Baseline）：降低方差的关键

直接用 `G_t` 加权有个严重问题：如果所有回报都是正的，那么**所有**动作的概率都会被提高，
只是提高幅度不同。这会让训练非常低效、抖动剧烈。

解决办法：减去一个**基线** `b`（通常取近期回报的滑动平均）：

```
weight = G_t - b
```

这样"比平均好"的动作权重为正、"比平均差"的为负，学习信号立刻清晰。

> 数学上可以证明减去任何**与动作无关**的基线都不改变梯度的期望值，
> 只降低方差。所以这是稳赚不赔的操作。

### 5.5 完整训练流程

```
for episode = 1 .. MAX_EPISODES:
    obs[], actions[], rewards[] = [], [], []
    reset 环境
    while 蛇还活着 and 未超时:
        obs   = encodeObservation(world)          ← 观测编码
        logits= net.forward(obs)
        probs = softmax(logits)
        a     = sample(probs)                     ← 采样动作
        r     = 环境执行 a 并返回奖励               ← 游戏步进
        记录 (obs, a, r)
    returns = 折扣累积(rewards, γ)
    baseline = 滑动平均(returns)
    用 returns - baseline 加权更新网络
    定期评估、保存权重、打印统计
```

## 6. 游戏侧需要提供的接口

### 6.1 现有代码的改造点

当前 `AIController` 是**具体类**（非虚），`GameScene` 里直接持有 `std::vector<AIController>`。
要接入神经网络，需要引入多态：

```cpp
// src/systems/AIController.h
class AIControllerBase {
public:
    virtual ~AIControllerBase() = default;
    virtual float decideAngle(float dt, const Snake& self,
                              const std::vector<Snake*>& snakes,
                              const std::vector<Food>& foods,
                              float mapW, float mapH) = 0;
    virtual void reset(float baseAngle) = 0;
    virtual const char* name() const = 0;      // 调试面板显示用
};

class RuleAI    : public AIControllerBase { /* 现有规则逻辑迁移过来 */ };
class NeuralAI  : public AIControllerBase { /* 神经网络策略 */ };
```

`GameScene` 持有 `std::vector<std::unique_ptr<AIControllerBase>>`。

> ⚠️ 这会影响 `rebuildSnakeList()` 那套裸指针逻辑，改造时要一并检查。

### 6.2 环境接口（训练用，与渲染解耦）

把"游戏一步"抽成一个不依赖 SFML 的纯逻辑接口：

```cpp
// src/rl/env.h
struct StepResult {
    std::vector<double> observation;   // 下一步的观测
    double reward;                     // 这一步拿到的奖励
    bool   done;                       // 是否结束（死亡/超时）
};

class SnakeEnv {
public:
    SnakeEnv(const GameConfig& cfg, uint32_t seed);
    std::vector<double> reset();                    // 开新的一局，返回初始观测
    StepResult step(int action);                    // 执行动作，推进一帧
    int observationSize() const;                    // = 20
    int actionCount() const;                        // = 3
};
```

`SnakeEnv` **不包含任何渲染代码**，因此可以每秒跑上万帧。

### 6.3 headless 训练模式

在 `main.cpp` 里加命令行分支：

```cpp
int main(int argc, char** argv) {
    if (argc > 1 && std::string(argv[1]) == "--train") {
        return runTraining();      // 无窗口，纯控制台
    }
    // ... 原有的图形模式
}
```

这样：

```bat
build\snake_game.exe --train              :: 高速训练，控制台打印进度
build\snake_game.exe --train --episodes 5000
build\snake_game.exe --play weights\best.txt   :: 加载权重，开着窗口看它玩
```

### 6.4 权重文件

沿用 MLP 自带的文本格式（见 `11-MLP-API参考.md`），放在 `weights/` 目录：

```
weights/
├── policy_best.txt       # 当前最优（按评估平均回报选）
├── policy_latest.txt     # 最新一版（用于断点续训）
└── policy_ep1000.txt     # 阶段性快照
```

## 8. 分阶段落地顺序（重要）

不要一次性全写完。建议按这个顺序，每步都能独立验证：

| 步 | 内容 | 怎么验证 |
|----|------|---------|
| 1 | `observation.h`：观测编码 | 写个小程序，打印某条蛇的 **32 维**观测，肉眼检查是否合理 |
| 2 | `env.h`：无渲染环境 reset/step | 用**随机策略**跑 1000 局，看平均存活帧数是不是个正常数 |
| 3 | `policy.h`：策略网络封装 | 未训练时三个动作的概率应接近 1/3 —— **训练面板的 `policy` 栏就是这个判据**（三项 ≈ 0.33 = 还没学到东西） |
| 4 | `reinforce.h` + `--train` | 跑 500 局，平均回报应有上升趋势 —— ⚠️ **但只看总回报会骗人**，要同时看「奖励构成」里是哪个分量在涨 |
| 5 | `NeuralAIController` | 加载权重，在图形模式里看它到底会不会玩 |

**第 2 步的"随机策略基线"千万别跳过**——它是后面判断"训练到底有没有效果"的唯一参照。
